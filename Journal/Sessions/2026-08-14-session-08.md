### WLS HATA ÇÖZÜMÜ

Yani WSL2 bir Linux sanal makinesi oluşturmak istiyor ama Windows’un sanallaştırma katmanından zamanında cevap alamıyor. HCS, Windows’un Host Compute Service tarafı; WSL2 distro’larını ve Docker’ın Linux backend’ini çalıştıran hafif VM altyapısının parçası. Microsoft’un benzer hata kayıtlarında da bu hata doğrudan VM/container yanıt timeout’u olarak görülüyor.

Senin sisteminde zincir kabaca şöyleydi:

Docker Desktop
      ↓
docker-desktop WSL distro
      ↓
WSL2
      ↓
Windows HCS / Hyper-V / Virtual Machine Platform
      ↓
Linux VM

Sorun şu noktadaydı:

Windows HCS / Hyper-V
        ↓
Linux VM oluşturuluyor
        ↓
VM cevap vermiyor
        ↓
TIMEOUT

Bu yüzden Docker’da ilk başta gördüğün:

vpnkit-bridge handshake failed

ve sonrasında:

Docker Desktop is unable to start

hataları büyük ihtimalle ikincil sonuçlardı. Docker WSL2 backend kullanıyor; docker-desktop WSL distro’su açılmazsa Docker Engine de başlayamaz. Docker’ın resmi dokümanı da Docker Desktop Windows tarafında WSL2 backend’in doğrudan WSL2 dağıtımına bağlı olduğunu belirtiyor.

Peki senin bilgisayarında neden oldu?

Burada %100 “tek sebep şuydu” diyemeyiz, ama elimizde çok kuvvetli kanıt var.

Sen çalıştırdığında:

sfc /scannow

Windows şunu söyledi:

Windows Resource Protection found corrupt files
and successfully repaired them.

Yani Windows sistem dosyalarında gerçekten bozulma vardı.

Daha sonra:

DISM /Online /Cleanup-Image /RestoreHealth

çalıştırdık ve:

The restore operation completed successfully.

aldık.

Sonra tekrar:

sfc /scannow

çalıştırdığında:

Windows Resource Protection did not find any integrity violations.

geldi.

Ve restart sonrasında daha önce:

wsl -d docker-desktop

komutunda aldığımız:

HCS_E_CONNECTION_TIMEOUT

kayboldu ve:

FatihBilig:/mnt/host/c/WINDOWS/system32#

shell’i açıldı.

Bu nedenle senin vakanda en güçlü açıklama şu:

Windows sistem/component dosyalarında bozulma
                 ↓
WSL2'nin kullandığı VM/HCS katmanı düzgün çalışamıyor
                 ↓
WSL2 VM boot edemiyor
                 ↓
HCS_E_CONNECTION_TIMEOUT
                 ↓
docker-desktop başlatılamıyor
                 ↓
Docker Engine çalışmıyor

Bu bir çıkarım, çünkü SFC bize “şu WSL dosyası bozuktu” diye spesifik dosya ismi vermedi; ama bozuk Windows dosyaları onarıldıktan sonra WSL VM’nin tekrar başlaması güçlü bir nedensel işaret. Microsoft da WSL sorun giderme rehberinde bozuk sistem dosyaları için SFC ve DISM onarımını öneriyor.

Neden wsl --status çalışıyordu ama distro açılmıyordu?

Bu da çok önemli.

Şu komut:

wsl --status

yalnızca WSL servisinin yapılandırmasını okuyabiliyordu:

Varsayılan Dağıtım: docker-desktop
Varsayılan Sürüm: 2

Ama:

wsl -d docker-desktop

gerçekten VM başlatmayı gerektiriyordu.

Dolayısıyla:

wsl --status
     ↓
Configuration oku
     ✅


wsl -d docker-desktop
     ↓
WSL2 VM oluştur
     ↓
HCS
     ❌ timeout

Bu yüzden “WSL kurulu ve status çalışıyor, nasıl bozuk olabilir?” durumu aslında çelişki değildi.

Docker neden sonradan 500 Internal Server Error verdi?

WSL VM’yi düzelttikten sonra bir sonraki katmana geçtik.

Önceden:

WSL VM        ❌
Docker Engine ❌

Sonra:

WSL VM        ✅
Docker Engine başlangıcı...

oldu.

Bu sırada:

dockerDesktopLinuxEngine/v1.55/version
500 Internal Server Error

gördük. Yani Docker CLI vardı ve Docker Desktop backend’ine erişebiliyordu ama Engine henüz tamamen hazır değildi. Sonrasında Docker’ın açılması da bunun startup süreci olduğunu doğruladı. Docker’ın troubleshooting belgeleri daemon/engine startup durumlarını ayrı bir katman olarak ele alıyor.

Kısacası senin yaşadığın problemi tek cümleyle anlatırsak:

Docker bozulmadı; Windows’un WSL2 sanal makinesini çalıştıran altyapısı düzgün cevap veremediği için docker-desktop Linux VM’i başlatılamadı ve Docker Engine de onun üzerinde çalışamadı. Sistem dosyalarını SFC + DISM ile onardıktan sonra WSL VM tekrar boot edebildi.

Bu olay sana WSL/Docker mimarisini anlamak açısından da güzel bir örnek oldu:

docker.exe
   │
   │ Docker API
   ▼
Docker Desktop
   │
   ▼
Docker Engine
   │
   ▼
docker-desktop (WSL2)
   │
   ▼
WSL2 VM
   │
   ▼
HCS / Hyper-V / Windows
