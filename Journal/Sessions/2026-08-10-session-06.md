# Service B Deployment

Yeni dosya oluşturuldu:

```text
deployments/service-b-deployment.yaml
```

Service B için Kubernetes Deployment tanımlandı.

Manifest içerisinde:

```text
apiVersion
kind
metadata
spec
replicas
selector
template
containers
image
imagePullPolicy
```

alanları kullanıldı.

Service B için:

```yaml
replicas: 1
```

tanımlandı.

Deployment selector:

```yaml
selector:
  matchLabels:
    app: service-b
```

Pod template label:

```yaml
labels:
  app: service-b
```

olarak ayarlandı.

Bu iki alanın eşleşmesi sayesinde Deployment'ın yöneteceği Pod'lar belirlendi.

Container:

```yaml
name: service-b
image: service-b:1.0
imagePullPolicy: IfNotPresent
```

olarak tanımlandı.

# Service B ClusterIP Service

Yeni dosya oluşturuldu:

```text
deployments/service-b-service.yaml
```

Service manifesti:

```yaml
apiVersion: v1
kind: Service

metadata:
  name: service-b

spec:
  selector:
    app: service-b

  ports:
    - port: 3001
      targetPort: 3001
```

olarak tanımlandı.

Öğrenilen:

```text
Service selector
→ hangi Pod'lara trafik gönderileceğini belirler

port
→ Service'in sunduğu port

targetPort
→ backend Pod üzerindeki uygulama portu
```

Service selector ile Service B Pod label'ı eşleşti:

```text
Service:
selector app=service-b

↓

Pod:
label app=service-b
```

# Rolling Update / Rollout

Service A Deployment Pod template'i değiştirildiğinde yeni bir ReplicaSet oluştu.

Gözlenen yapı:

```text
Eski ReplicaSet
↓
Eski Pod'lar

Yeni ReplicaSet
↓
Yeni Pod'lar
```

Geçiş sırasında:

```text
eski Pod → Terminating
yeni Pod → ContainerCreating
yeni Pod → Running
```

durumları görüldü.

Öğrenilen:

```text
Rollout
→ Deployment değişikliğinin yeni Pod'lara uygulanma süreci
```

Deployment yeni Pod'lara kademeli geçiş yaptı.

Rollout durumunu kontrol etmek için:

```powershell
kubectl rollout status deployment/service-a
```

komutu öğrenildi.

```text

```

İçerik:

```yaml

```

Öğrenilen:

```text
ConfigMap
→ gizli olmayan configuration değerlerini Kubernetes'te ayrı tutar
```

# configMapKeyRef

Service A Deployment içerisindeki doğrudan `value` kullanımı kaldırıldı.

Yerine:

```yaml
env:
  - name: SERVICE_B_URL
    valueFrom:
      configMapKeyRef:
        name: service-a-config
        key: SERVICE_B_URL
```

kullanıldı.

Akış:

```text
ConfigMap
↓
SERVICE_B_URL
↓
configMapKeyRef
↓
Container environment variable
↓
process.env.SERVICE_B_URL
```

Öğrenilen:

```text
ConfigMap
→ değerin tutulduğu Kubernetes resource'u

configMapKeyRef
→ ConfigMap içerisindeki belirli bir değere referans

env
→ değerin container'a environment variable olarak verilmesi

process.env
→ Node.js uygulamasının değeri okuması
```

# ConfigMap Değişikliği

ConfigMap environment variable olarak kullanıldığında mevcut çalışan container'ın environment variable'ı otomatik değişmez.

ConfigMap değiştirildiğinde:

```powershell
kubectl apply -f .\deployments\service-a-configmap.yaml
```

ile ConfigMap güncellenir.

Ancak yeni değerin container environment variable'ına gelmesi için yeni Pod oluşturulması gerekir.

Bunun için:

```powershell
kubectl rollout restart deployment/service-a
```

kullanılabilir.

Öğrenilen:

```text
ConfigMap güncellemesi
≠
çalışan process environment'ının otomatik güncellenmesi
```

# Readiness Probe

Service A Deployment'a Readiness Probe eklendi.

```yaml
readinessProbe:
  httpGet:
    path: /health
    port: 3000

  initialDelaySeconds: 5
  periodSeconds: 10
  timeoutSeconds: 2
  failureThreshold: 3
  successThreshold: 1
```

Readiness Probe şu soruya cevap verir:

```text
Bu Pod şu anda trafik almaya hazır mı?
```

Başarısız olduğunda:

```text
Pod Running olabilir
↓
Pod NotReady olur
↓
Service bu Pod'a trafik göndermez
```
